# DEC-002: Colour Contrast Values Rank Above the Imported Design System

| Field | Value |
|-------|-------|
| Type | Decision record (not an FR-BB requirement) |
| Status | Accepted |
| Date | 2026-10-10 |
| Decided by | Architect (`bb-architect`), under `CLAUDE.md` "Architect authority" (owner order of 2026-10-10, given to settle this conflict) |
| Owner | Business Analyst keeps the docs; Dev implements in #425 |

## 1. Context

Two sources disagree on four colour values.

- The imported design system (`docs/design-system/foundations.md`, `tokens.json`, synced from the owner's artifact on 2026-10-09) carries the source values.
- `FR-BB63` requires WCAG AA contrast (4.5:1 for body text). `FR-BB320` AC-1 found that the source values below miss it.

The design system is an external document in the sense of `CLAUDE.md` "Architect authority". Its README put it first in the order of authority, so a developer could not tell which value to implement.

## 2. Decision

1. Where a design-system colour fails the contrast target of `FR-BB63`, the contrast-passing value wins. The repo copy of the design system is corrected to that value; it does not keep the source value.
2. The values of `FR-BB320` AC-1 are accepted as written:

| Token | Theme | Source value | Decided value | Contrast before | Contrast after |
|-------|-------|--------------|---------------|-----------------|----------------|
| `color-text-muted` | light | `#8A94A6` | `#5F6B7D` | 3.06:1 on white | 5.40:1 on white |
| `color-text-muted` | dark | `#5A6A7E` | `#8FA0B4` | 2.90:1 on surface | 5.16:1 or more on every dark ground |
| `color-destructive-foreground` | dark | `#FFFFFF` | `#0F1623` | 3.52:1 on `#E06050` | 5.14:1 |
| gold badge text | light | `color-gold` `#C8A84B` | `#7A5E1A` on `color-gold-light` | 2.29:1 on white | 4.79:1 |

   The light-theme ratios and the two destructive ratios were recomputed for this record with the WCAG relative-luminance formula. The dark muted-text ratios are those of `FR-BB320` AC-1.
3. `color-gold` itself keeps its value. It is never used for text or as the only mark.
4. Hue, the role of each token and every other design-system rule stay as the design system states them. This decision changes lightness for contrast and nothing else.
5. A developer may adjust a decided value only as `FR-BB320` AC-1 allows: every ground in both themes stays at or above 4.5:1, the numbers are in the PR, and `index.css`, `tokens.json` and `foundations.md` change together.

## 3. Consequences

- #425 implements the values. It needs no further decision on colour.
- The repo copy of the design system and the owner's artifact differ on these four values until the artifact is updated. `tokens.json` records each difference in the token's usage note.
- A later sync from the artifact must not overwrite the decided values. The person who syncs compares against this record first.
- The owner may override this record with a direct order.
